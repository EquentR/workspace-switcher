# Workspace Switcher 简体中文 i18n 适配规格与实施规划

日期：2026-10-05。代码基线：e2499ac。

状态：规格草案；测试边界待确认；Issue 跟踪位置尚未配置，未发布。

本文依据当前会话和代码检查整理，不表示已实施汉化。首期范围采用上一轮推荐方案：图形界面英文/简体中文双语，跟随系统或手动选择，重新启动后生效。CLI 单列第二阶段，不计入首期完成条件。

## Problem Statement

中文用户目前需要理解英文的工作区管理、窗口状态、任务栏固定项、恢复设置和操作结果。仅翻译主窗口会遗漏编辑弹窗、托盘菜单、气泡通知、错误提示以及动态统计信息，形成中英文混杂。

项目目前没有语言资源、语言选择或资源回退机制。主窗口有 60 处包含英文字母的静态文本属性，创建/编辑弹窗有 11 处；该统计包含品牌名和按键名，不等于最终翻译项数量，也不包含绑定格式、回退值及 C# 动态文案。全产品初步估计约 150–200 个资源项，需在实施时提取、去重确认。

部分英文字符串同时参与业务解析和配置持久化，例如快捷键的自动分配、禁用选项。直接把这些值改成中文可能导致快捷键失效，或使旧工作区无法正常编辑和恢复。

## Solution

### 目标与使用体验

- 首期覆盖应用自己提供的全部图形界面文案，包括 WPF 界面、WinForms 托盘、操作状态、文件对话框标题及文件类型说明。
- 语言选项为“跟随系统 / English / 简体中文”；当前界面选择器用当前语言显示“跟随系统”，两种语言名称使用自称。
- 默认跟随系统。系统 UI 语言为简体中文（zh-CN、zh-Hans 及其区域变体）时使用简体中文，其他语言使用英文；繁体中文不自动映射为简体中文。
- 手动选择优先于系统语言；保存选择后提示“语言设置将在下次启动时生效。”，当前会话继续使用原语言，不自动重启。
- 英文是完整默认资源，简体中文资源缺项时回退英文，不向用户显示资源键或空白标签。
- 保留 Workspace Switcher 品牌名、按键名称、用户工作区名称与描述、应用名称、真实窗口标题和文件路径。

### 第二阶段：CLI 汉化点（独立交付）

- 将帮助说明、参数说明、示例解释、缺少参数、未知命令、配置不存在等信息提取为资源。
- 翻译列表表头：名称、图标、窗口数、任务栏固定项、快捷键、最后修改时间；验证中文字符、emoji 和长名称的显示宽度，不继续假设字符数等于终端列宽。
- 覆盖应用布局、创建快照、导入、导出、删除、任务栏应用/快照的成功与失败结果。
- 覆盖后台快捷键监听服务的启动、注册、触发、警告、退出信息。
- 保持所有命令名、参数名和退出码不变，例如 list、apply、snapshot、--launch；示例中的技术语法不翻译。
- CLI 在进程启动时读取相同语言偏好；修改偏好后，下次 CLI 调用生效。第二阶段不新增 CLI 设置命令或 --lang 参数。
- 使用适合中文输出的编码，并在实际 Windows 终端验证；不保证所有旧终端的 emoji 和中英文表格渲染一致。

## User Stories

1. 作为简体中文 Windows 用户，我希望首次启动时自动显示中文，以便无需先理解英文设置。
2. 作为其他语言 Windows 用户，我希望应用回退英文，以便仍能正常使用。
3. 作为用户，我希望手动选择简体中文或英文，以便按自己的偏好操作。
4. 作为用户，我希望恢复“跟随系统”，以便让应用语言与系统一致。
5. 作为用户，我希望语言选择在重启后保留，以便不用重复设置。
6. 作为用户，我希望知道语言设置何时生效，以便理解当前界面为何暂未改变。
7. 作为用户，我希望工作区列表、操作按钮和工具提示采用一致的中文，以便识别同一功能。
8. 作为用户，我希望用中文创建和编辑工作区，以便正确填写名称、描述及快捷键。
9. 作为用户，我希望名称为空时收到中文校验提示，以便知道如何修正输入。
10. 作为用户，我希望能看懂窗口数量、显示器数量和保存时间，以便判断布局内容及新旧程度。
11. 作为用户，我希望窗口状态标签和下拉选项显示中文，以便正确选择正常、最大化或最小化。
12. 作为多显示器用户，我希望主显示器、分辨率和位置用中文说明，以便正确选择恢复目标。
13. 作为用户，我希望坐标和尺寸标签清楚，以便调整窗口布局。
14. 作为用户，我希望自动保存提示明确，以便理解更改是否已经保存。
15. 作为用户，我希望理解“全局固定”与“仅此工作区”的区别，以便配置任务栏应用。
16. 作为用户，我希望任务栏没有布局时收到中文说明，以便知道如何保存当前布局。
17. 作为用户，我希望恢复选项用中文说明启动和关闭应用的影响，以便正确选择行为。
18. 作为用户，我希望导入和导出对话框有中文标题与筛选说明，以便选取正确的配置文件。
19. 作为用户，我希望操作结果显示中文和实际数量，以便判断操作是否完成。
20. 作为用户，我希望失败提示用中文描述应用可控的原因，以便采取下一步操作。
21. 作为托盘用户，我希望菜单、悬停说明和通知均使用选定语言，以便不用打开主窗口也能操作。
22. 作为已有用户，我希望旧工作区和快捷键继续有效，以便升级不会破坏配置。
23. 作为用户，我希望切换语言不修改我的名称、描述和应用信息，以便保留原始数据。
24. 作为用户，我希望中文在最小窗口尺寸和高 DPI 下仍可读，以便无需猜测被遮挡的按钮含义。
25. 作为英文用户，我希望新增中文支持后英文功能和布局仍然可用，以便升级不影响日常使用。
26. 作为维护者，我希望新增文案集中到资源中并支持英文回退，以便后续维护及增加语言。
27. 作为第二阶段的 CLI 用户，我希望帮助、结果和错误支持中文，以便理解命令行为。
28. 作为第二阶段的脚本用户，我希望命令语法和退出码保持不变，以便原有自动化继续运行。

## Implementation Decisions

以下为待实施的方案，不表示已有实现；测试边界待用户确认。

- 使用 .NET 自带 .resx 和 ResourceManager，英文为中性默认资源，简体中文使用 zh-CN 资源。不为两种语言引入外部翻译服务或第三方运行时依赖。
- 提供一个无 UI 依赖的本地化门面，统一语言解析、资源回退和带参数的消息格式化。各界面入口均调用该门面，不另建独立翻译表。
- 启动时先加载设置并确定本次语言，再创建主窗口及托盘。语言选择保存后只改变下次启动配置，禁止在当前会话部分切换。
- 在应用设置模型新增 language 字段，持久化值为 system、en、zh-CN；旧设置缺字段时视为 system，无效值同样回退 system。利用现有设置服务保存，保留既有设置项。
- 自动语言识别基于系统 UI 语言，而非地理区域；显式语言选择覆盖系统结果。zh-TW、zh-HK、zh-Hant 等不自动选择简体中文。
- 本地化只改变应用显示层。数字坐标解析和业务比较不因语言选择改变；日期显示按选定 UI 语言格式化。
- WPF 静态标签、工具提示、绑定回退文本及格式化统计均从资源取值；纯品牌、符号和按键名可保持字面值。应用全局样式仍复用现有主题。
- 统计和状态信息用完整消息模板及参数格式化，避免多段英文字符串拼接。计数可选分支采用完整模板。
- 现有主视图模型、工作区/窗口/任务栏项视图模型、工作区弹窗和托盘服务负责接入资源。语言选择可放在现有设置区域，不新增完整设置窗口。
- 将快捷键选项的稳定内部值与翻译后的显示名分离；绑定保存内部值，既有 Auto (1-5)、None (Disabled)、None 和修饰键值继续可读写。中文显示值不得传入业务解析器或写回配置。
- 窗口状态保留既有枚举和持久化表达，仅显示中文标签。显示器显示名由 UI 按索引、主显示器标识、分辨率和坐标格式化，不依赖解析已翻译的名称。
- Core 的已知业务失败应能在 UI 边界映射到中文消息；如当前异常类型无法可靠区分，补充稳定的原因标识。不得通过匹配英文异常正文选择翻译。
- 未知或外部异常保留原始诊断详情，外层操作说明和错误标题本地化。不要强求翻译系统返回的异常正文。
- 托盘在本次启动语言确定后生成菜单和通知；动态工作区名保持原始值，菜单重建继续使用同一语言。
- 中文字体采用 Windows 可用的中文字体回退；长说明允许换行，必要时调整固定列宽或最小尺寸。保留既有图标与 emoji 的语义。
- 不修改工作区配置字段名、枚举值、快捷键标识、文件扩展名、命令语法及退出码，不要求工作区文件迁移。

## Testing Decisions

### 测试边界（待确认）

优先在可观察行为边界测试：通过一个本地化门面验证“设置 + 系统 UI 语言 → 有效语言和实际文本”。复用现有设置服务、配置服务及快捷键公共接口验证旧数据行为；GUI 和托盘用实际程序进行人工验收。不单独为每个控件、资源键或内部类构造重复测试，不新增多套本地化测试入口。

### 自动化验证

- 本地化门面：system/en/zh-CN、缺失/无效设置，zh-CN/zh-Hans/zh-SG、英文及繁体系统语言的选择结果；明确验证繁体不会被误识别为简体。
- 消息格式化：0/1/多个窗口及固定项、包含中文和大括号的工作区名、可选任务栏信息，输出无丢失参数或占位符残留。
- 资源回退：故意缺失中文翻译时取得英文文本；只测试回退行为，不把“所有键均能读取”作为唯一验收。
- 设置兼容：复用 SettingsServiceTests 的临时目录和读写往返模式，验证旧设置缺 language、选项保存及无效值回退。
- 工作区兼容：复用 ProfileServiceTests 的配置往返方式，验证语言变化不改用户名称/描述、窗口状态及快捷键内部值。
- 快捷键兼容：沿用 HotkeyHelperTests 的数据驱动测试，验证旧 Auto/None 值的解析结果不变，并验证中文显示选项保存后仍解析为原按键。
- 日期显示：输入固定时间验证今天、昨天、近期和较早日期；避免测试依赖执行当天日期。
- 第二阶段 CLI：验证 --help、未知命令和缺少参数的实际输出与退出码，不在自动测试中执行恢复、关闭窗口或重启 Explorer 等有副作用的真实操作。

### 首期完成条件

1. 本文所有首期汉化点可在对应行为中验证；英文残留仅限品牌、技术标识、用户数据或外部系统内容等明确例外。
2. 各语言模式、保存和重启生效规则通过验证，无主窗口/托盘混用语言。
3. 旧设置和旧工作区无需迁移，快捷键、状态、窗口坐标及恢复选项行为不变。
4. 中文布局通过上述尺寸/DPI 检查，无未格式化占位符、资源键泄漏或乱码。
5. .NET 8 Release 构建成功；现有 55 项测试及必要新增行为测试通过。
6. 记录实际完成的人工检查与未验证场景，不能用编译成功代替 GUI 验收。

## Out of Scope

- 首期不包含 CLI 汉化；第二阶段有独立范围及验收。
- 不支持运行时无缝切换语言，不自动重启应用。
- 不增加繁体中文及其他语言，但资源结构允许以后扩展。
- 不翻译用户输入、外部窗口标题、第三方应用名、文件路径、系统诊断详情或堆栈。
- 不全文翻译 README、开发注释、技术日志和项目文档。
- 不改变现有工作区恢复、关闭应用、任务栏切换和快捷键分配语义。
- 不增加云端翻译服务、在线语言包下载、安装器本地化或界面主题重设计。
- 不为本功能重构整个 Core 异常体系；仅处理用户可见的已知业务失败。
